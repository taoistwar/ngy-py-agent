# 定时任务

定时任务让 Agent 按 cron 表达式自动开工：每个到点时刻**先创建一个会话，再在该会话里创建一个任务**，那次运行产生的会话、任务和结果都能在运行记录里找到。

入口：Web Admin 左侧「定时任务」。

## 一次运行发生了什么

1. 调度线程到点，认领这一分钟（同一分钟只会触发一次）；
2. 若这条任务上一次运行还在跑（`running`）或在等确认（`waiting`），本次跳过并记一条 `skipped`；
3. 新建一个会话（标题先取任务名 + 时间，任务结束后由命名线程改写）；
4. 在该会话里创建任务，检查点、权限确认、事件流与手动提交的任务完全一致；
5. 写一条运行记录，指向这次创建的任务与会话。

一次性任务（取消勾选「周期运行」）跑完第一次后自动暂停，不会排下一次。

## Cron 表达式

五个字段，用空格分隔，按**本机本地时间**解释：

```
分 时 日 月 周
```

| 写法 | 含义 |
| --- | --- |
| `* * * * *` | 每分钟 |
| `0 9 * * *` | 每天 09:00 |
| `*/5 * * * *` | 每 5 分钟 |
| `30 8-18/2 * * 1-5` | 工作日 08:30 起每两小时一次，到 18:30 |
| `0 0 1,15 * *` | 每月 1 号和 15 号 00:00 |
| `0 9 * * 7` | 每周日 09:00（周日也可写 `0`） |

- 每个字段支持 `*`、`*/N`、`N`、`N-M`、`N-M/S`，以及用逗号的列表。
- 「日」和「周」都写具体值时为 **或** 关系（`0 0 1 * 1` = 每月 1 号 + 每周一）。
- 写错的表达式在保存时就被拒绝，错误信息会指出是哪个字段。

## 界面

- **运行中的任务**：所有由定时任务启动、仍在 `running` / `waiting` 的任务，点「打开」跳到对应会话。
- **列表**：名称、cron、启用状态、下次运行、上次运行；点一行查看它的运行记录。
- **立即运行**：不管是否暂停都能跑一次，同样会留下运行记录。
- **暂停 / 启用**：暂停只是不再到点触发，定义与历史都保留。
- **删除**：连同运行记录一起删掉；已经跑出来的任务与会话保留。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/schedules` | 列表（含 `next_run_at` / `last_run_status` / `running`） |
| `POST` | `/api/schedules` | 新建：`cron`、`prompt`，可选 `name` / `agent_id` / `model_id` / `workspace_id` / `permission_mode` / `enabled` / `recurring` |
| `PUT` | `/api/schedules/{id}` | 局部更新，未出现的字段不动；`{"enabled": false}` 即暂停 |
| `DELETE` | `/api/schedules/{id}` | 删除定义与运行记录 |
| `POST` | `/api/schedules/{id}/run` | 立即运行一次（`trigger` 记为 `manual`） |
| `GET` | `/api/schedules/{id}/runs?limit=50` | 运行记录，最新在前 |
| `GET` | `/api/schedules/running` | 运行中的定时任务 |

运行记录里的 `status` 是**启动结果**：

- `started`：任务已创建，成败看同一条记录里的 `task_status`（读的是任务的当前状态）；
- `failed`：没启动起来，`error` 说明原因（例如绑定的模型已被删除）；
- `skipped`：上一次还在跑，这次跳过。

## 注意

- 定时任务无人值守：确认方式默认跟随全局设置，而全局若是「逐次确认」，运行会停在 `waiting` 等人在任务台里回答，直到超时失败（「运行中的任务」会把它列出来）。要让它自己跑完，在表单里把「确认方式」固定为 `auto_approve`；固定为 `deny_all` 则等于只让 Agent 读、不执行命令。
- 时区跟随服务进程的本地时间；跨时区部署时以服务器时钟为准。
- 删除或替换模型、工作区后，已有定时任务不会跟着改：工作区被删则该次运行不带工作区，模型被删则该次运行记为 `failed`。
